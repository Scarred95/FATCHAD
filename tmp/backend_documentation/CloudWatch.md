# CloudWatch Observability

## Structured Logging

**Files:** `backend/requirements.txt`, `backend/shared/api/middleware.py`

**Problem:** Lambda logs were plain text — CloudWatch couldn't filter or query them.

**What changed:** Added `aws-lambda-powertools` (AWS's official Python logging library for Lambda) and replaced the old `logging` module in `middleware.py`. Every request now writes a structured JSON log entry automatically:

```json
{
  "level": "INFO",
  "message": "request",
  "request_id": "cd3f48e5...",
  "method": "POST",
  "path": "/runs/abc/choice",
  "status_code": 200,
  "duration_ms": 38,
  "cold_start": true,
  "service": "fatchad"
}
```

This happens in the middleware which wraps **every** request — no changes needed in individual route functions. The `request_id` is already generated by the existing `RequestIDMiddleware`, so every log entry is traceable to a specific request.

## Dashboard

**File:** `infra/lib/api-stack.ts`

Added a CloudWatch Dashboard named `fatchad` with 4 widgets using **free built-in AWS metrics** (no custom metrics, no extra cost):

| Widget | What it shows |
|---|---|
| Lambda Errors | Error count per 5 min (Admin + Gameplay) |
| Lambda Duration | Average response time (Admin + Gameplay) |
| Lambda Invocations | Request count (Admin + Gameplay) |
| DDB Consumed Capacity | Read/Write units on `fatchad_user_data` |

Visible in AWS Console → CloudWatch → Dashboards → `fatchad` after the next CDK deploy.
